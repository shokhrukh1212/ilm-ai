## Problems encountered

1. **Webhook not registering — empty `url` in `getWebhookInfo`** — The backend started fine but Telegram showed no webhook URL. The symptom was a completely silent startup with no webhook log line.

2. **CORS 400 on OPTIONS preflight** — After fixing test mode, the deployed Vercel frontend received `400 Bad Request` on every OPTIONS preflight to the ngrok backend. All API calls from the deployed site were blocked.

3. **ngrok browser interstitial** — Even after CORS was fixed (OPTIONS → 200), the Telegram page showed "API serverga ulanib bo'lmadi" on load. The backend logs showed the request arriving but the frontend received ngrok's HTML warning page instead of JSON.

4. **`KeyError: 'prompt'` in quiz callback** — After selecting an answer in the Telegram inline quiz, the bot crashed. The `quiz_question_for_user` SQL query did not SELECT the `prompt` column, so `question['prompt']` raised a `KeyError`.

5. **Anthropic API credit exhausted** — `/quiz` command failed with `credit balance is too low`. Claude was being called for quiz generation but the account had no credits.

## Solutions

1. Set `IS_TEST_MODE=False` in `apps/api/.env`. The lifespan in `main.py` gates the entire webhook setup behind `not settings.is_test_mode`, so it was silently skipping registration on every startup.

2. Added `FRONTEND_URL=https://ilm-ai-mu.vercel.app` to `apps/api/.env` and restarted the backend. The CORS middleware builds its allowed-origins list at startup from this value; without it the list only contained localhost entries.

3. Added `"ngrok-skip-browser-warning": "1"` header to all `fetch` calls in `apps/web/lib/api.ts`. This bypasses ngrok's interstitial for all three fetch sites in the API client (main helper, chat stream, material content).

4. Added `q.prompt` to the SELECT in `quiz_question_for_user` in `apps/api/app/services/telegram_service.py` and included `"prompt"` in the returned dict.

5. Added credits to the Anthropic account via console.anthropic.com → Billing, then updated `ANTHROPIC_API_KEY` in `apps/api/.env`.
