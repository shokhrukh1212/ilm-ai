## Problems encountered

1. **JWT algorithm mismatch** — FastAPI auth was hardcoded to RS256 via JWKS. Supabase project used ES256 (newer projects use elliptic curve keys). This caused `"The specified alg value is not allowed"` on every API request.

2. **Database connection — IPv6 unreachable from WSL** — The Supabase direct connection string (`db.xxxx.supabase.co:5432`) resolves to an IPv6 address. WSL2 cannot reach IPv6 by default, causing `OSError: [Errno 101] Network is unreachable` on every DB call.

3. **asyncpg password auth failure with Session pooler** — After switching to the Session pooler (port 5432 via pooler.supabase.com), the list endpoint worked but `upload-complete` intermittently failed with `InvalidPasswordError`. Root cause: the Session pooler is flaky with asyncpg's prepared statement cache.

4. **Wrong embedding dimension** — The migration was originally written for OpenAI `text-embedding-3-small` (1536 dims). After switching to Cohere `embed-multilingual-v3.0` (1024 dims), the already-run migration still had `vector(1536)`, causing `"expected 1536 dimensions, not 1024"` on first paste ingest.

5. **Silent background task failures** — FastAPI `BackgroundTasks` swallows exceptions unless they propagate all the way out. When the DB connection failed inside `_mark_failed()`, the material stayed stuck as `"Jarayonda"` (processing) forever with no visible error.

6. **PDF viewer crash — pdfjs-dist + Next.js 15 webpack** — `react-pdf` sets `pdfjs.GlobalWorkerOptions.workerSrc` at module level using `new URL("...", import.meta.url)`. Webpack evaluates this during bundling before `import.meta.url` is a valid browser URL, causing `"Object.defineProperty called on non-object"` TypeError. Replaced entire PDF viewer with a native `<iframe>`, which solved it cleanly.

7. **Double PDF load in iframe** — React StrictMode (development) double-mounts effects, causing `getMaterial` to be called twice and returning two different signed URLs. The iframe reloaded with each new URL.

8. **OPENAI_API_KEY removed — embeddings provider switch** — Original Phase 2 used OpenAI for embeddings. Switched entirely to Cohere (already in the stack plan) since Anthropic has no embedding model. Required updating `embeddings.py`, `pyproject.toml`, migration dimension, and all tests.

## Solutions

1. Read `alg` from the JWT header before decoding; route HS256 to secret-based decode and RS256/ES256 to JWKS using `signing_key.algorithm_name` from PyJWKClient.

2. Switched `DATABASE_URL` to Supabase Transaction pooler (port 6543, `pooler.supabase.com`) which resolves to IPv4 and is reachable from WSL2. Added `ssl="require"` to `asyncpg.connect()`.

3. Switched from Session pooler to Transaction pooler and added `statement_cache_size=0` to the asyncpg connect call (required for transaction-mode pooling).

4. Ran `ALTER TABLE public.chunks ALTER COLUMN embedding TYPE vector(1024)` in Supabase SQL Editor to fix the already-run migration.

5. Added `logging.getLogger(__name__)` to `ingest.py`, wrapped `_mark_failed` DB call in its own try/except so a DB failure there is logged but doesn't prevent the error from being reported.

6. Replaced `react-pdf` + pdfjs-dist with a plain `<iframe src={signedUrl}>`. Removed all pdfjs worker setup code. Browser renders PDFs natively.

7. Stored the first received signed URL in a `useRef` and never updated it after that; the iframe always gets the same stable src.

8. Rewrote `embeddings.py` to use `cohere.AsyncClientV2`, changed vector dimension to 1024 everywhere (migration, tests), removed `openai` from `pyproject.toml`.
