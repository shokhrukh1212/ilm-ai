## What was done

### Phase 1 — Auth (completed)
- Supabase Auth with email magic link and Google OAuth
- Server-side session management via `@supabase/ssr` cookie-based client
- Next.js middleware for route protection and session refresh
- Onboarding wizard (3 steps: language + name, goal, daily minutes)
- Protected app shell with desktop sidebar and mobile bottom tab bar
- FastAPI JWT middleware using PyJWT with JWKS (RS256/ES256) and HS256 fallback
- `GET /api/v1/me` endpoint using Supabase PostgREST with user JWT
- `users` table migration with RLS, trigger for auto-creating profile on signup

### Phase 2 — Materials upload + RAG ingest (completed)
- File upload flow: signed URL from Supabase Storage + browser direct upload + upload-complete callback
- Paste text flow as alternative to file upload
- PDF/DOCX/TXT parsing (pypdf, python-docx, multi-encoding TXT)
- Language detection with langdetect
- Hierarchical chunking: parent (1500 tokens) + child (300 tokens, 60 overlap) using LlamaIndex SentenceSplitter
- Cohere `embed-multilingual-v3.0` embeddings (1024 dims) replacing OpenAI — better for Uzbek/Russian content
- pgvector HNSW index + tsvector full-text search index in Postgres
- Library UI: grid of material cards with type icons, status badges, polling for processing state
- Material detail page: PDF viewer (iframe), text viewer for paste/txt/docx, stats cards
- Active nav highlighting via client component using `usePathname()`

### Phase 3 — RAG chat with citations (completed)
- `migrations/0003_chat.sql`: `chat_sessions` and `chat_messages` tables with RLS policies and indexes
- `POST /api/v1/chat` SSE endpoint: streams `token` deltas → `citations` event → `done`
- Hybrid retrieval: Cohere `embed-multilingual-v3.0` cosine search + tsvector full-text, fused with
  Reciprocal Rank Fusion (k=60), then re-ranked from 20 → 5 with Cohere `rerank-v3.5`
- Tutor agent (Pydantic AI + claude-sonnet-4-6) with exact blueprint §5 Socratic prompt.
  Prompt injection defenses: XML-wrapped `<sources>`, message sanitizer, post-filter for stray `[n]` markers
- Sessions and messages fully persisted: citations jsonb, token counts, latency_ms, prompt_variant
- `ChatStream` component: renders token stream live, replaces `[n]` markers with clickable `CitationChip`
- Citation chips open a Sheet with an iframe PDF anchored to `#page=N`
- Thinking indicator: spinner + randomised Uzbek phrase referencing the user's question words while
  waiting for the first token (e.g. `«Fotosintez nima bu haqida» haqida manba ko'rmoqdaman…`)
- Markdown rendering: assistant responses parsed with `react-markdown` + `remark-gfm`, styled with
  custom Tailwind components (bold, bullets, headings, code blocks, blockquotes)
- Chat history sidebar (ChatGPT/Claude-style):
  - `GET /api/v1/chat/sessions?material_id=...` — up to 50 sessions newest-first
  - `GET /api/v1/chat/sessions/{id}/messages` — full message history for a session
  - Desktop: left sidebar (w-60) with relative dates (Bugun, Kecha, N kun oldin)
  - Mobile: History icon opens a Sheet with the session list
  - "Yangi chat" always starts fresh; clicking a session restores the full conversation

**Key decision:** Phase 2 stored embeddings with Cohere (1024-dim), not OpenAI (1536-dim). Using a
different model for query embedding would corrupt cosine similarity. Documented as inherited deviation;
queries also use Cohere `embed-multilingual-v3.0` with `input_type="search_query"`.

## Problems encountered — Phase 1

1. **JWT algorithm mismatch** — FastAPI auth was hardcoded to RS256 via JWKS. The Supabase project
   used ES256 (newer projects default to elliptic curve keys), causing
   `"The specified alg value is not allowed"` on every API request.

## Solutions — Phase 1

1. Read `alg` from the JWT header before decoding; route HS256 to secret-based decode and RS256/ES256
   to JWKS using `signing_key.algorithm_name` from `PyJWKClient`.

## Problems encountered — Phase 2

1. **Database connection — IPv6 unreachable from WSL** — The Supabase direct connection string
   (`db.xxxx.supabase.co:5432`) resolves to an IPv6 address. WSL2 cannot reach IPv6 by default,
   causing `OSError: [Errno 101] Network is unreachable` on every DB call.

2. **asyncpg auth failure with Session pooler** — After switching to the Session pooler
   (port 5432, pooler.supabase.com), the list endpoint worked but `upload-complete` intermittently
   failed with `InvalidPasswordError`. Root cause: Session pooler is flaky with asyncpg's prepared
   statement cache.

3. **Wrong embedding dimension** — The migration was originally written for OpenAI
   `text-embedding-3-small` (1536 dims). After switching to Cohere `embed-multilingual-v3.0`
   (1024 dims), the already-run migration still had `vector(1536)`, causing
   `"expected 1536 dimensions, not 1024"` on first paste ingest.

4. **Silent background task failures** — FastAPI `BackgroundTasks` swallows exceptions. When the DB
   connection failed inside `_mark_failed()`, the material stayed stuck as `"Jarayonda"` (processing)
   forever with no visible error.

5. **PDF viewer crash — pdfjs-dist + Next.js 15 webpack** — `react-pdf` sets
   `pdfjs.GlobalWorkerOptions.workerSrc` at module level using `new URL("...", import.meta.url)`.
   Webpack evaluates this during bundling before `import.meta.url` is a valid browser URL, causing
   `"Object.defineProperty called on non-object"` TypeError.

6. **Double PDF load in iframe** — React StrictMode double-mounts effects in development, causing
   `getMaterial` to be called twice and returning two different signed URLs. The iframe reloaded on
   every re-render with a new URL.

7. **OPENAI_API_KEY removed — embeddings provider switch** — Original Phase 2 used OpenAI for
   embeddings. Switched entirely to Cohere since Anthropic has no embedding model, requiring updates
   to `embeddings.py`, `pyproject.toml`, the migration dimension, and all tests.

## Solutions — Phase 2

1. Switched `DATABASE_URL` to the Supabase Transaction pooler (port 6543, `pooler.supabase.com`)
   which resolves to IPv4 and is reachable from WSL2. Added `ssl="require"` to `asyncpg.connect()`.

2. Switched from Session pooler to Transaction pooler and added `statement_cache_size=0` to the
   asyncpg connect call (required for transaction-mode pooling).

3. Ran `ALTER TABLE public.chunks ALTER COLUMN embedding TYPE vector(1024)` in Supabase SQL Editor
   to fix the already-run migration in place.

4. Added `logging.getLogger(__name__)` to `ingest.py`, wrapped the `_mark_failed` DB call in its
   own try/except so a DB failure there is logged but does not silently swallow the original error.

5. Replaced `react-pdf` + pdfjs-dist with a plain `<iframe src={signedUrl}>`. Removed all pdfjs
   worker setup code. The browser renders PDFs natively with no bundler involvement.

6. Stored the first received signed URL in a `useRef` and never updated it again; the iframe always
   gets the same stable src regardless of how many times the component re-renders.

7. Rewrote `embeddings.py` to use `cohere.AsyncClientV2`, changed the vector dimension to 1024
   everywhere (migration, tests), and removed `openai` from `pyproject.toml`.

## Problems encountered — Phase 3

1. **Pydantic AI `UserError: Set the ANTHROPIC_API_KEY` at import time** — Writing
   `tutor_agent = Agent(TUTOR_MODEL, ...)` at module level causes Pydantic AI to immediately
   instantiate the Anthropic provider and read `ANTHROPIC_API_KEY` from `os.environ`.
   Our key lives in pydantic-settings (`settings.anthropic_api_key`), not in the OS environment.
   The server failed to import the module before handling any requests.

2. **`Agent` has no `providers=` argument** — Attempted `Agent(..., providers=[AnthropicProvider(...)])`.
   The correct Pydantic AI API is `AnthropicModel("claude-sonnet-4-6", provider=AnthropicProvider(api_key=...))`
   passed as the `model=` argument to `Agent(...)`. Found by reading the installed source.

3. **`stream_ctx.usage()` deprecation** — `StreamedRunResult.usage` became a property in the
   installed version of pydantic-ai. Calling it as a method raised `PydanticAIDeprecationWarning`
   at runtime and returned incorrect data.

4. **`ANTHROPIC_API_KEY` not found at request time** — Even after fixing the import-time crash, the
   agent failed during requests. pydantic-settings loads the key from `.env` into
   `settings.anthropic_api_key`, but Pydantic AI's provider reads directly from `os.environ`.
   Since `.env` was never exported to the shell, `os.environ` had no key.

5. **UI hanging for 5+ minutes — SSE frame splitting bug (critical)** — The chat POST returned
   200 OK and the backend was streaming correctly, but the frontend showed nothing for minutes.
   Root cause: `sse-starlette` uses `\r\n` as its line separator (`DEFAULT_SEPARATOR = "\r\n"`),
   so frames are terminated by `\r\n\r\n`. The frontend was splitting the read buffer on `"\n\n"`
   only — which never matches a `\r\n\r\n` sequence. Frames never completed; no events ever fired.

6. **Token whitespace loss** — The SSE data-line parser used `.trim()` to strip the `data:` prefix,
   which also stripped the leading space that the LLM uses as a word separator. Words arrived
   concatenated without spaces.

7. **Chat history 500 — asyncpg returns jsonb as string** — The `GET /sessions/{id}/messages`
   endpoint crashed with a Pydantic `ValidationError`: `citations` expected a list but received a
   raw JSON string. asyncpg returned the `jsonb` column as an unparsed string because the value was
   written via `json.dumps(...) + ::jsonb` cast rather than a native Python object.

8. **History sidebar hidden by layout padding** — The `(app)` layout wraps all pages in
   `<main className="flex-1 px-4 py-6 md:px-8">`. The chat page's `h-[calc(100vh-4rem)]` did not
   account for this padding, clipping the sidebar and misaligning the chat height on all screen sizes.

## Solutions — Phase 3

1. Used a lazy singleton: `_tutor_agent: Agent | None = None` global + `get_tutor_agent()` function
   that initialises the agent on first call, inside the request lifecycle after settings are loaded.

2. Changed to the correct constructor:
   `AnthropicModel("claude-sonnet-4-6", provider=AnthropicProvider(api_key=settings.anthropic_api_key))`
   passed as `model=` to `Agent(...)`.

3. Changed `stream_ctx.usage()` → `stream_ctx.usage` (property, no parentheses).

4. Passed the API key explicitly via `AnthropicProvider(api_key=settings.anthropic_api_key)` so the
   provider never needs to look at `os.environ`.

5. Fixed the SSE parser to split frames on `/\r\n\r\n|\n\n|\r\r/` and lines on `/\r\n|\n|\r/`.
   Added a heartbeat `status` event emitted before retrieval starts, and wrapped retrieval in
   `asyncio.wait_for(..., timeout=15.0)` so the connection is never silently abandoned.

6. Changed the data-line parser to strip only one leading space
   (`if value.startsWith(" ") value = value.slice(1)`) per the SSE spec. Word-separator spaces now
   arrive intact.

7. Added `json.loads(raw)` when `isinstance(raw, str)` before constructing the Pydantic model,
   handling both the string and already-decoded-list cases from asyncpg.

8. Escaped the layout padding with `-mx-4 md:-mx-8 -my-6` negative margins on the chat page's
   outer div, and replaced the fixed `h-[calc(100vh-4rem)]` with `height: calc(100dvh - 3.5rem)`
   to correctly account for the mobile top bar.
