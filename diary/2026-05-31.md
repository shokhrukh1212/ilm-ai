## Problems encountered — Phase 6

1. **Only the Anthropic key is configured** — The merged Phase 4 quiz generator is hardcoded to GPT-4o, so quiz → gaps → plan couldn't run end-to-end with just `ANTHROPIC_API_KEY`, and the in-bot quiz would fail.

2. **PTB handler typing under mypy strict** — `CommandHandler`/`CallbackQueryHandler` expect a `Coroutine`-returning callback; the `@guard` wrapper was typed as returning `Awaitable`, which mypy strict rejected.

3. **Bot must not break the sandbox/tests** — Building the Application and calling `set_webhook` needs a token and network access that the sandbox lacks.

## Solutions — Phase 6

1. Added a Claude provider variant plus `resolve_provider()` that transparently switches an `"openai"` request to Anthropic when no OpenAI key is set — so generation "just works" with whichever key is present, with no config toggle.

2. Typed the `guard` alias as `Callable[..., Coroutine[Any, Any, None]]` (an `async def` returns a `Coroutine`), which satisfies the PTB handler signatures.

3. Gated the whole bot/scheduler startup behind `not IS_TEST_MODE and TELEGRAM_BOT_TOKEN`; the webhook route returns 200 as a no-op when the Application isn't built, so unit tests never touch the network. ngrok steps documented in the API README for live testing.

## Problems encountered — UI fix

1. **Quiz feedback showed raw markdown** — The grader/explainer returns markdown (`**bold**`, lists), but the quiz feedback was rendered as plain text, so users saw literal `**` asterisks instead of formatted text.

## Solutions — UI fix

### Bug fixes — quiz performance (completed)

**Issue 1: Quiz generation timing out (504)**
- `GENERATE_TIMEOUT_S` was 15 s. With no `OPENAI_API_KEY` set, `resolve_provider` silently fell back to Claude Sonnet, which takes 20–40 s to produce 10 validated JSON questions. The `asyncio.wait_for` ceiling fired first, the router returned 504, and the log showed "quiz generation timed out".
- Fix: wired in `OPENAI_API_KEY` (GPT-4o is the intended provider per the blueprint) and raised the timeout to 60 s. Added `OPENAI_API_KEY` to `.env.example` so it is no longer an invisible requirement.

**Issue 2: Quiz generation slow even with the right provider**
- The sources block fed up to 40 chunks (~12 k input tokens) into the LLM in one call. Halved `DEFAULT_MAX_CHUNKS` from 40 → 20 (~6 k tokens); `_even_sample` still spreads evenly across the full document so coverage is unchanged.

**Issue 3: Answer checking (explainer) very slow**
- Every answer — including MCQ where correctness is already decided deterministically — called Claude Sonnet 4.6 to produce 2–3 sentences of feedback. Sonnet is ~5–8× slower than Haiku for this simple task.
- Fix: switched `EXPLAINER_MODEL` from `claude-sonnet-4-6` → `claude-haiku-4-5-20251001`. The grading and short explanation are well within Haiku's capability.
